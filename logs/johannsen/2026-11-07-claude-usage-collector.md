# Counts-only Claude Code usage collector

Asked Claude Code to build a Claude Code counterpart to Joseph's Codex collector so QA work could be measured the same way. Before writing it, the agent inspected real local transcripts and found two differences from Codex: each API response records its own usage instead of a running total, and one response is written once per content block with its usage repeated (217 of 277 responses in one session had several entries). Counting entries would have inflated totals two to three times, so the collector sums unique message IDs inside a start/finish time window, across the session and its subagent transcripts.

`claude_usage.py` writes the same counters as `token_usage.py` and reuses its draft-run update, which gained an optional provider note and `tool_calls` field without changing Codex behaviour. Seven synthetic tests cover deduplication, window bounds, synthetic messages, subagent labels, null-not-zero for missing thinking counts, malformed versus partially written lines, draft-run filling with real validation, and that no prompt or path text is written. The first draft-run test failed on a macOS `/var` to `/private/var` path mismatch and an invalid fixture result value; both were fixed in the test. Both collector suites now run in CI.

A read-only dry run over 30 minutes of this session counted 32 responses, 31 tool calls, 5.10M input tokens of which 96.9% were cache reads, and 27.9K output tokens of which 24.1% were thinking. That window included PR review work and was not a recorded task, so no evidence file was written. QA tasks will use `start`/`finish` from now on.
